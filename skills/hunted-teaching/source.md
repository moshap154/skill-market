# teaching

AI に「SQL の JOIN がよく分からないので教えて」と頼むと、丁寧な説明が返ってきます。架空の場面で Skill を入れない AI に試させると、外したのは教え方でした（下の「Skill を入れずに頼むと」）。相手が何に使いたいかを知る前に、JOIN の種類を全部並べた長い講義をしました。手を動かす問題はほとんど出さず、正規表現を教える場面では手元の練習用のデータも開きませんでした。何日かに分けて教わる場面では、学んだことをどこにも残さず、次の日の新しい会話では前の回を拾えず、「昨日の作業を教えてください」と聞き返すか、別のデータ作業として始めました。

teaching は、人に新しいこと（SQL・正規表現・プログラミング・道具の使い方・仕事の知識など）を AI に教えさせるときの、AI が読む手順書（Skill）です。Skill は、エージェントが作業に合わせて読み込む手順書のファイルです。説明を聞いて分かった気になることと、自分でできることは違うので、相手が自分でできるようになるまでを手伝わせます。

向いているのは、Claude Code や Codex などのエージェントに、仕事で使う技術や道具を教わりたい人です。エンジニアでなくても使えます。一言で答えれば済む質問（「merge と rebase の違いを一言で」）には、この手順を使わずに一言で答えます。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。入れておくと、エージェントは Skill の説明文（どんなときに読むか）を見て、次のような頼みで読み込みます。

- 「SQL の JOIN がよく分からないので教えて」
- 「正規表現を使えるようになりたい。何日かに分けて教えて」
- 「昨日の続きからお願いします」

教わるときは、練習に使うデータや資料（自分の仕事の CSV など）を作業のフォルダーに置いておくと、AI はそれを開いて問題を出します。確実に読ませたいときは「teaching の Skill に従って」と名前で頼みます。

## Skill を入れずに頼むと

架空の場面で、Skill を入れない AI に同じ頼みを3回ずつさせました。教わる人の役は別の AI が演じ、練習の問題には、よくある間違いを含む答えを返しました（場面の中身と数え方は、下の「試した結果」）。

- 経理の人が「SQL の JOIN を教えて」と頼むと、3回とも、目的を聞く前に JOIN の種類を全部並べた講義から始めました。練習の問題を出したのは1回だけでした。手元の練習用の CSV には、顧客の表に無い売上が1件（5,000円）あり、INNER JOIN だと月次の合計から黙って消えます。この落とし穴は3回とも示しましたが、本人が自分で書いて気付く流れにはなりませんでした。本人が使う DuckDB に合わせて教えた回は無く、続きを読める出どころも3回とも示しませんでした。
- 何日かに分けて教わる場面では、3回とも、1日目の終わりに学んだことやつまずいた所をどこにも残しませんでした。2日目の新しい会話で「昨日の続きから」と頼むと、3回とも前の回を拾えず、「昨日の作業を教えてください」と聞き返すか、別のデータ作業として始めました。
- 総務の人が「正規表現を教えて」と頼む場面（Skill を書いたあとに作った場面）では、3回とも最初が長い講義で、手元の住所の一覧も開きませんでした。本人が書いた `\d{3}-\d{4}` では、全角の数字やハイフン無しの郵便番号が取れず、5件中2件しか取れません。5件中2件しか取れないと具体的に伝えた回はありませんでした。
- 「一言で教えて」と聞かれた場面では、3回とも一言で正しく答えました。

## SKILL.md に書いてあること

AI が読むファイルです。使うだけなら読まなくてかまいません。どう動くかを確かめたいときは [SKILL.md](../skills/teaching/SKILL.md) を開いてください。

- 作業のフォルダーに相手の資料やデータがあれば、教える前に開いて見ます。何に使いたいかと今どこまで分かるかを1〜2問で聞き、相手が知っているものにたとえ、相手が使う道具の書き方で教えます。
- 1回に教えるのは、目的に要るいちばん手前の1つにします。種類を全部並べません。
- 目的に近い小さな問題を、相手の手元のデータで出し、答えを書いてもらいます。つまずきやすい所は、先に説明するより問題で踏んでもらい、件数や合計を確かめさせて気付いてもらいます。
- 「これで合っていますよね？」には、うなずく前に結果を一緒に確かめます。答えには、合っている所と違う所を返事の中で具体的に返します。気付いてもらう問いは1回までにし、気付けなければ答えと直し方を示します。直し方は、手元のデータの全部の形で通るかを確かめてから示します。
- 終わりに次の一歩を1つと、続きを読める出どころ（公式の docs など）を示します。
- 何回かに分けるときは、回の終わりに学びの記録（目的・できるようになったこと・つまずいた所・次にやること）を、作業のフォルダーの Markdown のファイル（`学びの記録.md` など）に書き足し、次の回はそれを読んでから、前の回の要点を短い問いで思い出してもらって始めます。

## 試した結果

2026年11月に、架空の場面で試しました。教える AI（Claude の Sonnet）は、練習用のファイルを置いたフォルダーの中で作業します。教わる人の役は別の AI が、決めた設定のとおりに演じました（場面2だけは、決めた文を順に送りました）。記録は、Skill の有無を伏せて、別の AI（Claude の Opus）が採点しました。場面ごとに守ってほしいこと（観点）を決め、それぞれを満たしたかを見ました。

- 場面1：経理の人に SQL の JOIN を教える。手元の CSV に、顧客の表に無い売上が1件ある。本人は INNER JOIN の答えを書き「これで全部出ますよね？」と聞く。観点は7個。
- 場面2：何日かに分けて JOIN を教わる。1日目の最後に「今日はここまで」と言い、2日目は前の会話を持たない新しい会話で「昨日の続きから」と頼む。観点は6個。
- 場面3：「merge と rebase の違いを一言で」。落とし穴の無い場面で、Skill を入れたせいで講義や問題を始めないかを見る。観点は3個。
- 場面4：総務の人に正規表現を教える。手元の住所の一覧に全角の数字やハイフン無しの郵便番号が混ざっていて、本人の答えでは5件中2件しか取れない。Skill の最初の版を書いたあとに作った場面です。観点は7個。

観点は、たとえば場面1なら「最初の説明が短く、種類を全部並べる講義にしていない」「手元の CSV で問題を出した」「答えの取りこぼしを具体的に指摘した」、場面2なら「1日目の終わりに学びの記録を残した」「2日目にそれを読んで続きから始めた」のようなものです。表の数字は、満たした観点の数を3回分足したものです。分母は観点の数×3回です。採点は観点ごとに「満たした・一部だけ・満たさない」の3段で、表は「満たした」だけを数えています。観点は Skill の書き手が決めたもので、観点ごとの重みは同じに置いています。独立に試したのは場面ごとに3回です。

| 場面 | Skill なし | Skill あり |
|---|---|---|
| 1 1回で JOIN を教える | 6/21 | 19/21 |
| 2 何日かに分けて、続きから | 0/18 | 13/18 |
| 3 一言で答える（落とし穴なし） | 9/9 | 9/9 |
| 4 正規表現を教える（Skill の最初の版のあとに作った場面） | 3/21 | 18/21 |

- 「Skill あり」は、Skill の本文を必ず読ませた条件です。表は3回目の版の数字です。差の大半は最初の版で出ていて、場面1・2・4は最初の版で 16/21・10/18・15/21、2回目の版で 15/21・12/18・14/21 でした。場面4は最初の版を書いたあとに作った場面ですが、2回目と3回目の直しには場面4の外しも使いました。直すのに使った場面で測っているので、表の数字は甘く出ている可能性があります。
- Skill を置くだけにして、読むかどうかを AI に任せた条件も試しました（作者が使っているほかの Skill 31本と一緒に置いた状態）。教える場面の6回（場面1・2・4を2回ずつ）はすべてこの Skill を読みました。観点は、場面1が 12/14、場面2が 7/12、場面4が 9/14 で、必ず読ませた条件より低めでした。場面3（一言）の1回は読まずに、観点は全部満たしました。
- Skill ありで残った外しは、場面2で、つまずいた所を記録のファイルには詳しく書いたのに、本人への返事では短く済ませた回があったこと、場面4で、全角も取れる書き方を示す前に会話が終わった回があったことです。
- 1回の費用（Skill なし → あり）は、場面1が 0.10〜0.20 → 0.13〜0.20 ドル、場面2が 0.11〜0.12 → 0.19〜0.24 ドル、場面4が 0.06〜0.13 → 0.09〜0.12 ドルでした。場面2は、記録を書いて読む分が増えます。場面3は、どちらも 0.01 ドル未満で、かかった時間も Skill なしの10〜11秒に対してありで11〜12秒と、ほぼ変わりませんでした。
- 教わる人は AI が演じたもので、人が本当に身についたかは測っていません。教わる人の PC の DuckDB は使っていません。教える AI は、自分の作業の環境の SQLite・DuckDB・Python で確かめました。作業する AI が Sonnet 以外のとき、Claude Code 以外のツールで読み込まれるかは、確かめていません。

## 入れ方

```
npx skills add itoken-lab-jp/skills -g --skill teaching
```

`-g` は、プロジェクトごとではなく、自分のユーザーのどのプロジェクトでも使える場所に入れる指定です。手順の本文は [SKILL.md](../skills/teaching/SKILL.md) です。入れ方の詳しい説明（置かれる場所、ツールごとの違い）は [README](../README.md#入れ方) にあります。
