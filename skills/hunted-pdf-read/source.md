# pdf-read

PDF から文字を取り出すスクリプトを AI に書かせると、表の列や縦書きが崩れがちです。スキャンした PDF は、文字の層（PDF に埋め込まれた文字のデータ）が無いので、取り出しても空になります。pdf-read では、エージェントはスクリプトを書きません。まず PDF に文字の層があるかを調べ、あれば Poppler の `pdftotext -layout` で列の位置を保ったまま読み、無ければページを画像にして tesseract で OCR します。

OCR は日本語の帳票（請求書・伝票・決算の表など）で、マイナスを表す ▲ やカンマをよく誤ります。そこで、tesseract が語ごとに出す確信度が低い語や、`4A410.000` のように形のおかしい数字を拾い、そのページの画像をエージェントが直接見て読み直します。金額・数量・日付・コードは、拾った所が無くても画像と突き合わせます。画像を読めないエージェントでは、確かめていない値をそう書いて報告します。

この Skill には道具が入っていません。Poppler（`pdftotext` や、ページを画像にする `pdftoppm` を含むコマンド群）と tesseract を、エージェントが動く PC に一度入れてください。Windows は winget、Mac は Homebrew、Linux は apt で入ります。日本語の OCR には、標準のデータより精度の高い [tessdata_best](https://github.com/tesseract-ocr/tessdata_best) の `jpn.traineddata` と、縦書き用の `jpn_vert.traineddata` を使います。入れ方と置き場所は [SKILL.md](../skills/pdf-read/SKILL.md) の「道具の場所」にあります。

## 速さと精度

公開されている2つの PDF で測りました。財務省の[令和8年度予算のポイント](https://www.mof.go.jp/policy/budget/budger_workflow/budget/fy2026/seifuan2026/01.pdf)（18ページ、表と金額が多い）と、国税庁の[令和7年分 確定申告の手引き](https://www.nta.go.jp/taxes/shiraberu/shinkoku/tebiki/2025/pdf/060.pdf)（72ページ、文章が多い）です。

文字の層がある PDF は、`pdftotext -layout` で全ページを、予算のポイントは 0.05秒、手引きは 0.84秒で読みました。メモリは 20MB 以下です。

スキャンの読み取りは、2〜8ページを画像にし、紙を読み取ったように傾けて雑音を足してから tesseract で OCR しました。正解は、同じページの文字の層です。

| PDF | 文字の一致（7ページの範囲） | OCR の時間（1ページ） |
|---|---|---|
| 予算のポイント（7ページ） | 81〜90% | 3.5〜10.6秒 |
| 手引き（7ページ） | 85〜94% | 3.8〜10.4秒 |

- 文字の一致は、空白を除き、正解とOCR の結果で文字ごとの数を突き合わせた割合（F 値。正解の文字の何割を読めたかと、読んだ文字の何割が正しいかの両方を合わせた値）です。読む順の違いは数えていません。
- 金額（カンマや ▲ の付いた数字）は、予算のポイントで測りました。手引きには金額がほとんどありません。45個の金額があるページでは 84% が正解と同じ形で読めました。OCR は、▲ や ＋ の記号を落とし、`1,151,978` を `151,978` のように桁の一部を落とし、数字そのものを抜かしていました。金額が4〜14個のページのうち3ページでは、1つも同じ形で読めませんでした。

OCR の結果だけでは金額を信用できないため、この Skill では、金額・数量・日付・コードを、エージェントがページの画像と突き合わせます。作者が2026年11月6日に、財務省の予算資料と国税庁の確定申告の手引きの別の PDF（14ページと48ページ）で、傾きや雑音を足さずにページの画像を OCR したときは、文字の一致が 95〜98% でした。エージェントに画像を直接読ませると 99.6〜100% になりましたが、1ページに12〜20秒と数千トークンかかりました。そのため、全部を画像では読ませず、OCR で読んでから怪しい所だけを画像で確かめます。

- 測った環境：2026年11月14日、クラウドの Linux（x64、4コア）、Poppler 24.02.0、tesseract 5.3.4、tessdata_best の `jpn`、画像は 200dpi。
- 実際のスキャンは、ここで作った画像より傾きや汚れが大きいことが多く、精度はこれより下がることがあります。本物のスキャンでは測っていません。

手元で測り直すには、Linux か Mac に Poppler・tesseract・Pillow を入れ、上のリンクから2つの PDF をダウンロードして、PDF と tessdata_best のフォルダーを渡します。自分の PDF を渡すこともできます（正解は文字の層なので、文字の層のある PDF に限ります）。

```
python3 tools/pdf-read/bench.py 01.pdf 060.pdf --tessdata <tessdata_best のフォルダー> --pages 2,3,4,5,6,7,8
```
