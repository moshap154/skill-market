# chart-making

chart-making は、AI にデータからグラフを作らせるときの、AI が読む手順書（Skill）です。Skill は、エージェントが作業に合わせて読み込む手順書のファイルです。AI にさせるのは次の4つです。グラフで言うことを1文で置く。小さい差は、軸を絞った点や折れ線か、基準との差の棒で見せ、値の棒の軸は途中から始めない。形を指定されたら、その形で作り、読み比べにくいときだけ読みやすい形を1枚添える。出来た画像を自分で開いて直してから渡す。

「推移は折れ線、比較は棒」のような種類の対応表は書いていません。架空の場面で Skill を入れない AI（Claude の Sonnet、描く道具は matplotlib、各場面3回）に試させると、「どの店が伸びているか分かるグラフを」のように問いを添えた頼みでは、8つの場面の24回すべてで、問いに合う種類のグラフを選んだからです。うまくいかなかったのは、頼み方が形を決めてしまう場面でした（下の「Skill を入れずに頼むと」）。「グラフにして」とだけ頼むと12本の折れ線を12色で重ね、「差が分かりやすい棒グラフを」と頼むと棒の軸を途中から始め、「円グラフで」と頼むと、3回のうち2回は読み比べにくいことを言わずに渡しました。

向いているのは、Claude Code や Codex に、CSV や表の数字から資料に載せるグラフの画像を作らせている人です。数字を集計するだけのときや、Web の画面やダッシュボードの色・部品の見た目を整えるときには使いません。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。入れておくと、エージェントは Skill の説明文（どんなときに読むか）を見て、次のような頼みで読み込みます。

- 「店舗ごとの月次の売上が store_sales.csv にあります。グラフにしてください」
- 「施策のあと満足度が上がったことが伝わる棒グラフを作って。差が分かりやすいように」
- 「2年で売上の構成がどう変わったかを役員に見せたいので、円グラフで作って」

確実に読ませたいときは「chart-making の Skill に従って」と名前で頼みます。

## Skill を入れずに頼むと

架空の11の場面で、Skill を入れない AI に同じ頼みを3回ずつ、合わせて33回させました。問いを添えた頼みが8場面、問いを言わない頼みが2場面、形を指定した頼みが1場面です。グラフは Python の matplotlib で描かせ、出来た画像も見て採点しています（Skill の有無を比べた7場面の中身と数え方は、下の「試した結果」）。

- 問いを添えた8場面では、3回とも合う形を選びました。12店の「伸びている店と落ちている店」は、伸び率を並べ替えた正負の棒。単位の違う2つの推移（売上と来店客数）は、左右に別の目盛りを取るグラフ（2軸）ではなく、最初を100とした指数で1つの軸に。2つの拠点の対応時間は、平均の棒ではなく、ばらつきの見えるヒストグラムと箱ひげ図。47都道府県は、並べ替えた横棒でした。日本語が □ になる文字化けも、33回で一度も出ませんでした（描く前に、使える日本語のフォントを自分で確かめていました）。
- 「store_sales.csv をグラフにしてください」とだけ頼むと、3回とも、12店の折れ線を12色で重ねて凡例で読ませるグラフを作りました。データの中には、伸びている2店と落ちている2店があります。返事でその増減に触れたのは1回だけで、その回も落ちている1店を落としました。残りの2回は売上の高い店と低い店を挙げただけで、うち1回は、落ちている店を「上位の店」として挙げました。
- 「差が分かりやすい棒グラフを」と頼むと、3回とも、棒グラフの縦軸を 4.0 から始めました。5点満点で 4.19 が 4.29 になった 0.1 点の差が、棒の高さでは何倍にも見えます。3回とも、画像の隅に小さく「縦軸は 4.0 から」と注記し、返事でも「実際より大きく見えます」と伝えています。隠してはいませんが、その画像が資料に貼られると、注記は読まれにくくなります。軸を絞るなら点や折れ線にする、棒のままなら基準との差を棒にする、といった形は、一度も出しませんでした。
- 「円グラフで」と頼むと、3回とも円を2つ並べました。区分の色と順はそろえましたが、区分名は凡例でしか読めません。円を2つ並べると、8つの区分の差を角度と面積で見比べることになります。3回のうち2回は、その読み比べにくさに触れませんでした。
- 「月別の売上をグラフにして」のような簡単な頼みでは、3回とも、出来た画像を自分で開かずに渡しました（返事に「見た目は確認していません」と書いています）。ほかの場面でも、開いてラベルの重なりに気付いたのに、直さずに「少し重なっています」と書いて渡した回が3回ありました。

## SKILL.md に書いてあること

AI が読むファイルです。使うだけなら読まなくてかまいません。下は中身の要約で、全文は [SKILL.md](../skills/chart-making/SKILL.md) にあります。

- 描く前に、このグラフで言うことを1文にします（例：「新宿店と博多店が伸び、梅田店と仙台店が落ちている」）。問いの無い頼みでは、聞き返さずにデータを見て、変化や差のいちばん大きい話を選びます。その1文を題と、返事の最初に書きます。
- 系列や項目が多いとき（色で見分けられるのは7つくらいまで）は、全部を同じ強さで載せません。言うことに関わる系列だけに色を付けてほかは灰色の線で残す、増減を並べ替えた棒にする、1枚の中に項目ごとの小さなグラフを並べる、のどれかにします。名前は凡例でなく、線や棒のそばに書きます。
- 小さい差を見せたいときは、差が見える範囲に軸を絞り、点や折れ線で描きます（位置で読むので、0 から始めなくてよい）。差の大きさは数字でも図に書きます。値そのものの棒は、長さで読まれるので、軸を途中から始めません。「棒グラフで」と指定されたときは、基準（施策の前の平均など）との差を棒にします。0 が基準になるので、軸を切らずに差が見えます。
- 形を指定されたら、その形で作ります。その形の弱い所は手当てし（区分名と値を直接書く、言うことに関わる区分を強調する）、言うことがその形では読み比べにくいとき（円を2つ並べて区分ごとの差を見せる、など）だけ、読み比べやすい形を2枚目として1枚添えて、1文で伝えます。
- 迷いやすい形を4つだけ書いています。単位の違う2つの推移は指数にして1つの軸に、構成の比較は同じ軸の棒に、群の比較は平均だけでなく分布を、値が何桁にも広がる2つの量の関係は対数の軸に、です。
- 描く前に使える日本語のフォントを確かめて指定します。保存した画像を自分で開き、日本語が □ になっていないか、文字が重なっていないか、単位と期間があるか、題を隠しても言うことが読み取れるかを見ます。崩れは直してから渡します（直しは2回まで）。
- 返事は、言うことの1文、それを支える数字、保存した場所だけにします。
- 言うことも形も明らかな頼みでは、1枚作り、開いて見て、渡します。聞き返す、別の形を添える、分析を書き足す、はしません。

書く前に、公開されている可視化の Skill 13本の SKILL.md を読みました。文は写していません。インストール数の多いものは次のとおりです。

ほぼ全部が「データの関係（推移・比較・構成・分布・相関）からグラフの種類へ」の対応表を持っていて、中身もほぼ同じでした。試した範囲では、その部分は AI が言われなくてもできたので、この Skill には入れていません。13本のうち3本が、出来た画像を自分で見る手順を書いていました。日本語のフォントに触れたものはありませんでした。

グラフの選び方と誤解を生む描き方については、次の資料を読み、場面と採点の観点を作る材料にしました。

- Financial Times の [Visual Vocabulary](https://github.com/Financial-Times/chart-doctor/tree/main/visual-vocabulary)
- Claus Wilke の [Fundamentals of Data Visualization](https://clauswilke.com/dataviz/)
- Datawrapper のブログ（[2軸のグラフ](https://www.datawrapper.de/blog/dualaxis)、色の使い方）
- 総務省統計局の[なるほど統計学園](https://www.stat.go.jp/naruhodo/9_graph/kihon.html)

次の3つは、これらの間でおおむね一致しています。棒は 0 から始める、平均だけの棒は分布を隠す、色で見分ける系列は7つくらいまで。意見が割れているのは、円グラフ、折れ線の 0 始まり、2軸です（Datawrapper は2軸を2018年に否定し、のちに条件つきで認めています）。割れている所は、禁止ではなく「頼まれたら作り、読みやすい形を添える」と書きました。

## 試した結果

2026年11月に、架空の場面で試しました。作業する AI（Claude の Sonnet）は、CSV の入ったフォルダーの中で、Python（matplotlib・pandas）を使って作業します。1往復だけで、頼む人の返事はありません。記録と出来た画像を、Skill の有無を伏せて、別の AI（Claude の Opus）が採点しました。場面ごとに守ってほしいこと（観点）を決め、それぞれを満たしたかを見ました。どの場面にも共通の観点が4つあります（日本語が読める、何の数字か分かる、出来た画像を自分で開いて確かめた、返事が短い）。

Skill の有無を比べた場面は次の7つです。

- 場面 A：12店×24か月の売上を「グラフにしてください」とだけ頼む。伸びている2店と落ちている2店がある。観点は7個。
- 場面 B：四半期ごとの満足度（5点満点、0.1 点の上昇）で「施策のあと上がったことが伝わる棒グラフを。差が分かりやすいように」と頼む。観点は8個。
- 場面 C：8区分の売上の2年分で「構成がどう変わったかを、円グラフで」と頼む。観点は8個。
- 場面 D：12か月の売上を「グラフにしてください」と頼む。落とし穴の無い場面で、Skill を入れたせいで重くならないかを見る。観点は6個。
- 場面 E：場面 A と同じデータで「どの店が伸びていて、どの店が落ちているかを見せたい」と問いを添えて頼む。観点は7個。
- 場面 F：300店の広告費と売上（値が何桁にも広がる）で「広告費をかけた店ほど売上が多いのかを見たい」と頼む。観点は7個。
- 場面 G：売上（億円）と来店客数（千人）の36か月で「客数は減っているのに売上は伸びている、を1枚で」と頼む。観点は7個。

表の数字は、満たした観点の数を3回分足したものです。分母は観点の数×3回です。採点は観点ごとに「満たした・一部だけ・満たさない」の3段で、表は「満たした」だけを数えています。観点は Skill の書き手が決めたもので、観点ごとの重みは同じに置いています。

| 場面 | Skill なし | この Skill を読ませる |
|---|---|---|
| A 問いの無い頼み（12店） | 12/21 | 20/21 |
| B 差が分かりやすい棒グラフを | 14/24 | 24/24 |
| C 円グラフで | 18/24 | 23/24 |
| D 月別の売上（落とし穴なし） | 14/18 | 17/18 |
| E 伸びた店と落ちた店 | 19/21 | 21/21 |
| F 広告費と売上 | 15/21 | 21/21 |
| G 客数と売上 | 15/21 | 17/21 |

- 右の列は、Skill の本文を必ず読ませた条件です。本文は、書いたあとに経緯を知らない読み手に読ませ、2通りに読める所（棒と指定されたときの扱い、添える枚数、直しの回数の上限など）を直しました。場面 A・C・D は直したあとの版、場面 B はそのあと差の見せ方を書き直した版、場面 E〜G は直す前の版の数字です。E〜G は直したあとの版では3回そろえて試していません（直す前の版の A〜D は、順に 21/21、24/24、23/24、17/18 で、ほぼ同じです。差の見せ方を書き直した版で A・D・E を1回ずつ走らせ、崩れが無いことを見ました）。場面は、Skill なしの外し方を見てからこの Skill を書いたので、この Skill がその場面に合わせて書かれている分、数字は甘く出ている可能性があります。
- 場面 A は、3回とも、伸びた2店と落ちた2店だけに色を付け、残りの8店を灰色にし、線のそばに店名を書き、題に結論を書きました（欠けた1つは、返事が長かった回です）。場面 B は、3回とも、施策の前の平均（4.19 点）との差を棒にしました。0 が基準なので軸は切らず、施策のあとの +0.07〜+0.12 点が棒の長さで見えます。同じデータで「棒」の指定を外して頼むと（3回、採点はしていません）、3回とも、縦軸を 4.1〜4.4 に絞った折れ線に、前後の平均と差を書き込みました。初めの版の本文は「棒は 0 から描いて差を注記で書く」としていて、点は同じ 24/24 でしたが、0.1 点の差が棒の高さではほとんど見えなかったので、書き直しました。場面 C は、3回とも、頼まれた円（変化の大きい2区分を強調し、区分名を直接書いたもの）に、増減を並べた棒を1枚添えました。
- 場面 F は、Skill なしでは3回のうち1回、大半の点が左下に固まったまま渡しました。Skill ありでは3回とも対数の軸にしました。
- 場面 D（落とし穴なし）は、Skill なしで欠けた4つのうち3つが「出来た画像を開いていない」で、Skill ありでは3回とも開きました。1回の平均で、時間は 13秒 → 23秒、道具を呼ぶ回数は 2.7回 → 4.7回に増えました。増えたのは画像を開いて見る分で、グラフの枚数と人への問いは増えていません。
- 場面 G は、Skill の有無によらず3回とも指数化した折れ線を選びました。どちらも3回とも欠けた観点が1つあり（季節の山をならすために12か月の合計どうしで比べ、36か月全体の増減より小さい数字を伝えた）、Skill では変わりませんでした。差の2点は返事の長さです。
- 作業する AI の1回の費用（Skill なし → あり。採点の分は含みません）は、場面 A が 0.05 → 0.08 ドル、B が 0.05 → 0.07 ドル、C が 0.06 → 0.12 ドル（2枚作るため）、D が 0.02 → 0.05 ドルでした。
- Claude Code には、組み込みの dataviz という Skill があります（色と見た目の作りが中心）。Skill を本文ごと読ませるのでなく、フォルダーに置くだけにして、読むかどうかを AI に任せた条件も試しました（この Skill の作者が使っているほかの Skill 34本と一緒に置いた状態）。場面 A〜D とほかの2場面の、グラフの頼み14回のすべてでこの Skill を読みました。うち12回は、組み込みの dataviz も一緒に読んでいます。集計だけの頼み（「合計と平均を教えて」）の2回は、どちらも読みませんでした。この Skill を置かず、組み込みの dataviz だけが読まれた条件では、場面 A が 15/21（12色を重ねるのはやめたが、伸びた店と落ちた店の4つを伝えた回は無い）、B が 15/24（3回とも棒の軸を 4.0 から始めた）、C が 19/24、D が 18/18（3回とも画像を開いた）でした。画像を開いて見ることは組み込みの dataviz でも足り、A〜C はこの Skill を足した分だけ変わります。
- 場面ごとに3回ずつで、数は少ないです。1往復だけの場面で、作ったグラフに頼んだ人が直しを頼む往復は試していません。描く道具は matplotlib だけで、Excel・PowerPoint のグラフ、plotly などの HTML のグラフ、ダッシュボードは試していません。日本語のフォントが入っていない環境、作業する AI が Sonnet 以外のとき、Claude Code 以外のツールで読み込まれるかも、確かめていません。見た目の好み（色、線の太さ）は採点していません。

## 入れ方

```
npx skills add itoken-lab-jp/skills -g --skill chart-making
```

`-g` は、プロジェクトごとではなく、自分のユーザーのどのプロジェクトでも使える場所に入れる指定です。手順の本文は [SKILL.md](../skills/chart-making/SKILL.md) です。入れ方の詳しい説明（置かれる場所、ツールごとの違い）は [README](../README.md#入れ方) にあります。
