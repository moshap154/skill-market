# task-tracking

AI エージェントは、目の前の1件は終わらせます。すでにやることの一覧（TODO.md など）があれば、済んだ項目のチェックの印も直し、翌日はその一覧を読んで続きから始めます。一覧がまだ無い所では、残りを落とします。会話の中で「今週中にお願い」「これは急ぎません」と頼みが足されていくと、AI はその日の作業を済ませ、残りを返事の中で「次回やります」と並べて終わります。翌日の新しい会話は前の会話を持たないので、期限のある頼みも、人の返事を待っていた頼みも、どこにも残っていません。

task-tracking は、Issue や Linear のような票の道具（やることを1件ずつ記録する道具）を使っていないリポジトリやフォルダーで、やることを1つのファイル（TODO.md）に書かせて保たせる、AI が読む手順書（Skill）です。git を使わない文書だけのフォルダーでも使えます。

向いているのは、票の道具を使っていない所で、AI に何日かに分けて仕事を頼む人です。やることを全部 Issue などに書いている所だけで使うなら、入れなくてかまいません（入れても、TODO.md は作らせません）。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。入れておくと、エージェントは Skill の説明文（どんなときに読むか）を見て、次のような場面で読み込みます。

- 会話の中で、その日にやらない頼みが出た（「今週中に」「後ででいい」「佐藤さんの返事が来たら」）。
- 「今日はここまで」と言われて止める。
- 新しい会話で「昨日の続きをお願い」と頼まれた。
- 「打ち合わせのメモを、何日かに分けて進められる形にして」と頼まれた。

エージェントが読み込むかどうかは、エージェントがその場面だと気づくかどうかで決まります。確実に読ませたいときは「task-tracking の Skill に従って」と名前で頼みます。

## Skill を入れずに頼むと

架空の場面で、Skill を入れない AI に同じ頼みを3回ずつさせると、次のように外しました（場面の中身と数え方は、下の「試した結果」）。

- 会話の中で頼みが足されていく場面で、その日にやらなかった頼みを、3回ともどこにも書きませんでした。翌日の新しい会話は、期限のある頼み（月末の会議に要る集計）と、人からのデータを待っていた頼みを落としました。
- 打ち合わせのメモをやることの一覧にする場面で、何ができたら終わりかを、3回とも項目に書きませんでした。8件の一覧が 58〜88 行になり、読み返すには長すぎました。

一方で、すでに TODO.md がある場面では、Skill がなくてもよくできました。印を直し、待ちの項目を正直に待ちと書き、翌日は TODO.md と git の履歴を読んで続きから始めました（別に試した場面で、3回とも、決めた観点を全部満たしました）。

## SKILL.md に書いてあること

AI が読むファイルです。使うだけなら読まなくてかまいません。どう動くかを確かめたいときは [SKILL.md](../skills/task-tracking/SKILL.md) を開いてください。

- 書き先を決めます。リポジトリやフォルダーの決まりが先、票の道具があればそこ、どちらも無ければ直下の `TODO.md` 1つです。会話と、エージェントのメモリ（ツールが持つ、会話をまたいで覚えておく機能）だけには置きません。
- 止めるときにまとめて書こうとすると落とすため、その日にやらない頼みは、出たその場で書きます。
- 1行に1件を動詞で書き、その下に「終わり」（試験が通る、このコマンドでこれが出る、のように確かめられる状態）を1行付けます。終わりを確かめてから、済みの印を付けます。
- 人やデータを待つ項目は「途中・待ち」にして、できた所、残り、誰の何をいつまで待つかを書きます。
- 何をするかが決まっていない頼み（「使いやすく」など）は、作業にせず「誰に何を聞く」の1件にします。
- 軽く保ちます。長いメモ、日程表、優先度の段、ラベルは足しません。
- 続きから始めるときは、ファイルと実物（フォルダーの中身、コード、履歴）を照らし、食い違えば実物を正としてファイルを直します。
- 一覧にある1件だけを頼まれたときは、その1件をやって印を直すだけにします。一覧を作り替えたり、次の項目に進んだりしません。

やる順や、入りきらないときに何を削るかを決める手順は入っていません。

## 試した結果

2026年11月に、架空の場面で試しました。作業する AI（Claude の Sonnet）は、題材のファイルが入ったフォルダーの中で、コマンドを走らせ、ファイルを読み書きしながら作業します。頼む人の言葉は、決めた台本のとおりに送りました（場面1だけは、別の AI が頼む人の役をしました）。2日目は、前の会話を持たない新しい会話で始めます。記録は、Skill の有無を伏せて、別の AI（Claude の Opus）が採点しました。場面ごとに守ってほしいこと（観点）を決め、それぞれを満たしたかを見ました。

- 場面1：1人で面倒を見ている社内の道具（シフト表）のリポジトリで、打ち合わせのメモ（9行）を「何日かに分けて進められるように、管理できる形にして」と頼む。観点は10個。
- 場面2：同じリポジトリで、やることの一覧が無いまま、会話の中で頼みを足していく（すぐやるもの、今週中のもの、人からのデータを待つもの、急がないもの）。「今日はここまで」で止め、翌日の新しい会話で「昨日の続きをお願いします」「いま何が残っていますか？」と聞く。観点は7個。
- 場面3：場面2と同じ流れを、git を使わない文書のフォルダー（展示会の出展準備。頼む人はエンジニアではない）で行う。観点は8個。
- 場面4：すでにある TODO.md の1件を「やっておいて」と頼むだけの、落とし穴の無い場面。Skill を入れたせいで遅くなったり、頼まれていないことを足したりしないかを見る。観点は4個。

表の数字は、満たした観点の数を3回分足したものです。分母は観点の数×3回です。採点は観点ごとに「満たした・一部だけ・満たさない」の3段で、表は「満たした」だけを数えています。観点は Skill の書き手が決めたもので、観点ごとの重みは同じに置いています。

| 場面 | Skill なし | Skill あり |
|---|---|---|
| 1 メモを管理できる形にする | 18/30 | 24/30 |
| 2 会話で頼みが積み重なり、翌日に続きから | 3/21 | 21/21 |
| 3 同じことを、git を使わないフォルダーで | 6/24 | 24/24 |
| 4 一覧の1件をやるだけ（落とし穴なし） | 10/12 | 12/12 |

- 「Skill あり」は、Skill の本文を必ず読ませた条件です。
- Skill を置くだけにして、読むかどうかを AI に任せた条件も試しました（作者が使っているほかの Skill 28本と一緒に置いた状態）。場面2は、3回のうち2回が、1日目に頼みが足された所でこの Skill を読み、3回の計は 21/21 でした（読まなかった1回も、翌日に、同じ場所に置いた引き継ぎの Skill を読んで残りを拾いました）。場面3は3回とも読み、22/24 でした。場面1は2回とも読み、16/20 でした（2回なので分母は 20）。場面4は2回とも読まず、8/8 でした（読まなくてよい場面です）。
- 費用は増えます。場面を最初から最後まで1回通すのにかかった額は、場面2が Skill なしで 0.25 ドル、ありで 0.36 ドル、場面3が 0.14 ドルと 0.23 ドル、場面4が 0.035 ドルと 0.05 ドルでした。
- 場面4の「Skill あり」は、Skill の本文の最初の版では、3回とも、頼まれていない README に説明を1行足し、「次は5に進めます」と報告に添えたため、7/12 でした。1件だけの頼みでは手を広げない、と本文に足して測り直したのが表の 12/12 です。場面1〜3の数字は、足す前の本文で測ったものです（足したあとの本文では、場面2を1回だけ測り直し、7/7 でした）。
- 場面ごとに3回ずつで、数は少ないです。作業する AI が Sonnet 以外のとき、Claude Code 以外のツールで読み込まれるか、何週間も続く作業で TODO.md が育ちすぎないかは、確かめていません。

## 入れ方

```
npx skills add itoken-lab-jp/skills -g --skill task-tracking
```

`-g` は、プロジェクトごとではなく、自分のユーザーのどのプロジェクトでも使える場所に入れる指定です。手順の本文は [SKILL.md](../skills/task-tracking/SKILL.md) です。入れ方の詳しい説明（置かれる場所、ツールごとの違い）は [README](../README.md#入れ方) にあります。
